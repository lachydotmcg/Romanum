# Disabled OpenAI Responses adapter

`createOpenAIAdapter().complete(request, callOptions)` defaults to disabled. Neither keys nor environment flags enable it. The [disabled engine integration](EXECUTION.md) now connects it to Ask/Chats, durable dispatch holds, the existing application tool loop and normalized ledger settlement. Credential configuration, prices and wallet policy remain unchanged. The adapter performs one bounded nonstreaming POST to `https://api.openai.com/v1/responses`, with redirects forbidden, `store:false`, `background:false`, `service_tier:default`, and no automatic retries or model substitution. The single-call/store/deadline design was adapted from the existing local OpenAI Chat transport draft; its dirty source and harness/reviewer consumers were preserved. Current reasoning tool calls use Responses.

The allowlist comes from the existing foundation: `gpt-6-luna`, `gpt-6.1-sol`, `gpt-6-astra`. `gpt-6-sol` has a different cache-read price and is not substituted for GPT-6.1 Sol. Luna accepts `none` through `max`; Sol/Astra reject `none`. Default effort is `medium`, with `reasoning.context:current_turn`. Application function tools use `strict:false`, preserving the app's original schema; the app must validate each returned input and authorize execution. Native hosted tools, server fees, regional/fast/flex modes, remote images, files, audio, custom endpoints, Pro/beta modes, background work and streaming are unsupported. Returning such output or an unverified pricing modifier fails closed. This is a bounded adapter subset, not a claim to implement all catalog capabilities.

User text/base64 images and native function results translate to Responses input. Reasoning tool rounds require the private `continuation`, which preserves ordered native reasoning/message/function items, opaque encrypted reasoning, message phases and call IDs. Exact preceding history, model, tools, instructions, output cap and reasoning/cache settings are prefix-bound. Mutation, model changes, missing native reasoning history, orphaned/duplicate/missing tool results or assistant prefill are rejected. Continuation input must originate in trusted owner-scoped server history; its digest is not authentication. `text` concatenates visible response text. The integration preserves native phases privately and never exposes, logs or places opaque continuation in UI/accounting records. Earlier completed Chat Completions tool history is converted to visible historical context.

`compileOpenAIRequest` returns deeply frozen translated `body`, serialized `json` and `requestHash`. The hash includes those exact UTF-8 request bytes, fixed endpoint and request-format version; it excludes credentials. `complete` snapshots before looking up a key and transmits exactly the compiled bytes. Trusted `callOptions.binding` can require the persisted request hash and canonical dispatch timestamp. The integration's reviewed monetary bound covers the full native context, including history, schemas, framing, images and reasoning; application admission remains 200,000 and output stays capped at 16,000 including reasoning. Actual input plus output must fit the native window. The adapter checks supplied bounds and usage but does not reserve credits itself.

Completed results contain exact verified response model/message ID, complete disjoint token usage, independent `providerCostNanoUsd`, and attribution `evidence`. OpenAI ordinary input is `input_tokens - cached_tokens - cache_write_tokens`. Reasoning details are a subset of output; they are not added. Truncation and refusal keep attributable usage while exposing no tool calls or continuation. Truncation can cost input and reasoning without visible text. The final protocol evidence for a truncated response means the envelope was completely received/validated; it does not claim the answer completed.

Any timeout, cancellation, HTTP rejection, network failure, malformed report, model mismatch, unsupported fee or failed semantic validation after submission returns `submission:uncertain`. No failure asserts zero cost or releases a hold. Complete counters on a failed response do not become final accounting evidence. Response bodies are capped at 4 MiB while reading, text at 1 MiB, tool JSON at 64 KiB, tools at 16 and output items at 128. Fatal UTF-8 decoding, strict JSON snapshots and a 25-second deadline cover fetch and body consumption, including a noncooperative injected transport. Raw provider errors never enter results.

`execution-accounting/adapter-evidence.ts` maps trusted adapter output to the pure contract. A candidate remains separate from a quote, marked-up debit and settled receipt. The integration enforces owner-scoped durable attempt/hold binding, one dispatch, reviewed bounds, global final-response uniqueness and atomic normalized ledger settlement. Post-claim ambiguity, mismatched identities, unsupported pricing and over-bound/over-quote evidence retain the hold. Production still requires separate activation/entitlement and PostgreSQL concurrency checks. Native continuation is private to one invocation; crash replay is disabled. Preserve the pinned rate card until an explicit historical registry supports future card changes. The legacy `CallUsage` path cannot flatten Anthropic TTLs or price every catalog model.

[Reasoning](https://developers.openai.com/api/docs/guides/reasoning) specifies total output/reasoning caps, incomplete responses and default encrypted content for stateless `store:false` requests. [Responses create reference](https://developers.openai.com/api/reference/typescript/resources/responses/methods/create) supplies the envelope, usage and native function item shapes. Installed official SDK 7.23.0 also confirms nullable message phases. The catalog's existing long-context multiplier remains tested independently; adapter policy limits keep requests below that tariff threshold.

Only synthetic injected transports were exercised. There were no live API calls, authentication/entitlement checks, token-counting transmissions, payment activation or deployment. Real cache eligibility, image dimensions, disconnect behavior and provider wire compatibility remain unverified live.
