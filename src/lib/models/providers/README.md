# Disabled Anthropic Messages adapter

`createAnthropicAdapter(options).complete(request, callOptions)` performs at most one native Messages HTTP request. It defaults to `executionEnabled: false`; the catalog/readiness review stays unchanged and all Anthropic models remain unselectable. This change adds no engine hook, key configuration, ledger settlement or tool executor. It imports no provider SDK and performs no request at import/factory time.

## Integration contract

Contracts live in `providers/types.ts`; foundation model IDs and `NormalizedUsage` remain unchanged. The exact requested Anthropic model ID is required. `translateAnthropicRequest` is a pure, strict translator from a separate system string, user text/base64 images, assistant text/tool calls and tool-result messages. Assistant tool calls become native `tool_use` blocks; immediately matching results are grouped into the following user message before user text. Orphan, duplicate or missing results and assistant prefill are rejected. Tools use object input schemas and allowlisted names. No fallback list, model substitution, automatic continuation or paid retry is sent.

Completed results include server-only `continuation` data with ordered native content and opaque thinking signatures. Persist it privately and pass it back on the corresponding assistant history entry alongside the matching text/tool calls. Never forward it to the UI, treat it as user text or log it. A SHA-256 prefix digest checks the exact preceding translated messages, selected model, system, tools and cache/thinking settings before replay. It detects a changed prefix; it is not authentication or an authorization boundary. Only trusted server history may supply continuations. Start a new compatible context when changing the bound prefix/model; this adapter rejects replay into changed context rather than mutating signatures. Truncated results have no continuation.

Supply `maxTokens` and a trusted `maxInputTokens` bound covering the full translated history, framing, tool schemas and vision tokens. Combined bounds must fit the foundation's 200,000-token policy and 16,000-output ceiling. Omit optional fields rather than passing non-JSON values. The translator rejects extra properties, cycles, nonfinite numbers, unsafe prototype keys and excessive depth/size. It does not estimate or reserve credits. A reviewed integration must recheck readiness, owner access and cancellation, then atomically obtain the existing hold before enabling/submitting each attempt.

`complete` returns a discriminated `AnthropicResult`:

| Result | Integration action |
| --- | --- |
| `completed`, ordinary text | Persist the exact model, stop reason and complete normalized usage. |
| `completed`, `tool_use` | Validate every returned `ToolCall.input` against the application's authoritative schema and recheck permissions before execution. Calls are intents, not authorization. |
| `completed`, `truncated: true` | Display incomplete text explicitly. All tool calls are dropped, including superficially complete calls; no continuation is attempted. |
| `completed`, `refusal` | Preserve the refusal stop reason. No fallback or retry is attempted. |
| `failed`, `submission: not_submitted` | No transport call was made. Existing integration may release its unused hold under its own policy. |
| `failed`, `submission: uncertain` | A bill cannot be ruled out. Keep/reconcile the hold; do not automatically release or retry. |

`onText` delivers provisional text only. It can precede a failed/truncated result, so consumers must reconcile displayed text with the final outcome. No tool is executed and no partial tool call is emitted. `usageComplete: false` marks the latest validated cumulative usage as partial evidence, not settlement data. A failed semantic response can still have `usageComplete: true` after a complete, validated usage report; this flag proves usage-report completeness, not permission to settle or release funds. The adapter calls foundation `normalizeUsage` but never changes prices or balances.

## Transport and parsing

The destination is fixed to `https://api.anthropic.com/v1/messages`, redirects are forbidden, and the API version is `2023-06-01`. Requests explicitly use `service_tier: standard_only`. Frontier models also pin `inference_geo: global`; Haiku 4.5 omits that unsupported parameter. Key presence is checked on each enabled call, server-side; missing/removed/invalid keys prevent submission. Keys are sent only in the authorization header to that fixed origin. Raw HTTP error bodies, transport exception messages and provider diagnostic messages never enter results or logs. Results use a fixed error vocabulary. The factory rejects a browser environment. Dependency injection is for trusted server integration and synthetic testing; never accept options, a key getter or a transport from request JSON.

Streaming is the default; nonstream JSON uses the same response/usage validation. The parser handles split UTF-8 bytes, LF/CRLF/CR, multiline SSE data, ping/comments and valid unknown extension events. It requires ordered message/block lifecycle events, final cumulative output usage and `message_stop`. Blocks retain their indices; tool JSON is parsed as an object only after the whole message completes. Invalid JSON, duplicate IDs, undeclared tool names, pricing modifiers, server-tool charges, model changes and unsupported content fail closed. Ordinary input, cache read and 5-minute/1-hour creation tokens remain separate; cumulative snapshots replace prior counts rather than being added. Cache creation without a detailed breakdown requires the trusted request's explicit TTL.

Response limits are 4 MiB total, 256 KiB per SSE frame, 1 MiB text, 64 KiB per tool JSON, 16 tool calls, 128 blocks and 20,000 data events. Request JSON is capped at 8 MiB; JSON nesting at 32 levels. These are adapter policy limits. Cancellation and a 60-second default deadline cover both fetch and body consumption. A deadline returns even if an injected transport ignores abort; the real transport must honor its AbortSignal to close underlying work. Timers/listeners/readers are cleaned up. There is one submission regardless of error status.

## Supported subset and live limits

This adapter covers native global/standard Messages, ordinary text, base64 JPEG/PNG/GIF/WebP inputs, application client tools and optional automatic 5-minute/1-hour prefix caching. Mixed 5-minute/1-hour usage reports are normalized. The request exposes one TTL, not mixed cache breakpoints. Frontier models use adaptive thinking with omitted display because current Opus/Fable models cannot disable thinking. Omitted thinking/signature and redacted blocks are preserved privately in order; readable reasoning is rejected and never emitted. Haiku keeps its default thinking configuration. Custom thinking/effort, late system messages, URL/file images, documents, server tools, beta features, fast/priority inference, custom endpoints and provider fallback are unsupported. The foundation's broad capability flags do not activate those features.

No live provider request was made. Model entitlement, provider authentication, actual latency, disconnect behavior, cache eligibility/hit rate, image validity/dimensions and evolving wire behavior remain untested live. The integration must validate/review those before enabling models. Synthetic fixtures exercise protocol shapes; they contain no customer prompts, credentials or actual recordings. Run `node --experimental-strip-types --test tests/anthropic-provider.test.mjs tests/model-*.test.mjs`.
